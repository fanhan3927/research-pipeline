# 投资人材料包编排层

对应 `docs/PRD.md` 第五部分「投资人材料包」。这是分发链、研发链之外的**第三条支线**，
只有在两条主链都跑完之后才触发，产出 Pipeline、研究报告、PPT 大纲之外的另外两份对外材料。

## 前置条件（触发前必须检查）

Teaser 和 Infographics 提示词依赖的内容（退出预期、可比公司倍数、护城河判断）横跨两条链，
所以触发前先检查这两样是不是都在：

```
python scripts/project_status.py --project-dir <project_dir>
```

- `03_pipeline/` 下要有 `Pipeline_对外版_*.xlsx`（分发链跑完）
- `05_screening/` 下要有研判报告（研发链至少跑到定性研判）

**估值（`06_valuation/`）不是硬性前提**——如果项目是天使轮等早期阶段、按规则跳过了
`hardtech-preipo-valuation`，Teaser 里就没有"退出预期"这个板块，不强求。但如果连
`03_pipeline/` 或 `05_screening/` 都缺，就不要往下走，提示用户先把对应的链跑完：

> "生成 Teaser/信息图提示词需要两条链都至少跑到出对外版的程度。现在缺 XX，
> 要不要先去把这一步补上？"

## 只出对外版，没有内部版

这两个产出物设计上就是给机构投资人看的营销材料，不像 Pipeline/研究报告那样需要"内部版
留判断依据、对外版清洗"——**起草时只能读两条链已经生成的对外版文件**（`Pipeline_对外版_*.xlsx`、
`研究报告_对外版_*.md`），不要去翻内部版、研判备忘、疑点清单这些 L3 文件来"找亮点"。
这本身就是最可靠的隔离机制：内部专属的内容压根不会进入起草者的视野，不需要标记后再删除。

起草完成后仍然要跑一遍关键词兜底扫描（同 Pipeline/研究报告用的机制），当作最后一道保险：

```
python scripts/check_external_safe.py --input <草稿文件> --project-dir <project_dir>
```

命中不阻塞，但要在人工确认节点里过一遍。

## 步骤 1：生成 Teaser

**结构不锁模板**——参考格式（标题、投资亮点分点论述、有的话附可比公司表、结尾），但具体
分几点、每点讲什么，跟着项目实际情况走，不强求每个项目都套"估值性价比/业绩确定性/发展
潜力/退出预期"这四类。比如天使轮项目没有退出预期数据，就不写这一节，不要为了凑结构编数字。

**必须遵守的信息披露规则**：跟 Pipeline 的加工层是同一套铁律（见
`hardtech-project-triage-matching` 第 1.3 节）——估值定价依据、折扣/倒挂情况、回购条款
存在与否、锁定期、已知重大风险、数据口径，这些**必须如实写**，不能因为 Teaser 是"营销材料"
就只挑好听的说。Teaser 是精简版的推介材料，不是选择性披露的广告。

**取材顺序**：
1. `Pipeline_对外版_*.xlsx` —— 项目简介、入场估值、定价逻辑、投资形式、亮点、目标上市地、
   预计申报时间、退出估值、退出方式、流动性安排
2. `研究报告_对外版_*.md` —— 团队、技术护城河、财务与运营数据、退出路径分析里的客观内容
3. 如果 `06_valuation/` 有产出，只取**退出估值区间**和**目标 IRR 对应的市值预估**这类
   面向标的价值判断的结论；入场价格上限本来就不会出现在对外版材料里，Teaser 也不例外

存到 `08_investor_materials/Teaser_对外版_<日期>.md`。

## 步骤 2：推荐信息图风格 + 生成 Infographics 提示词

用户会把提示词拿去 ChatGPT 的图片生成模型里用，所以最终格式统一用**结构化 JSON**
（不是自然语言段落）——这类模型对 JSON 结构化 prompt 的解析很稳定，且对"这个板块必须
放哪几个精确数字/标签"的控制力比自然语言段落强，适合金融数据类信息图这种容不得数字
写错位置的场景。

### 风格库与选型逻辑

7 种参考风格，各自适配的构图任务不同，选型时按这个逻辑判断，不要固定死用哪 3 个：

| 风格 | 构图任务 | 适合什么样的项目 |
|---|---|---|
| Codex 研讨会 Slides 网格 | 3x3 多页幻灯片缩略图拼贴 | 不适合单张投资海报，除非要出"多页材料预览图" |
| 3x3 B2B SaaS 演示文稿概览 | 3x3 多页产品页面拼贴 | 同上；但里面的 KPI 卡片/趋势图单元适合借鉴局部样式 |
| 雅典娜之鸮信息图海报 | 单张高密度海报，中心大图+多分区+对比表+时间轴 | **护城河/竞品对比丰富、有清晰融资时间轴**的项目 |
| 克劳德·香农复古信息图海报 | 单张海报，标题区+备忘录式数据框+中心技术流程图+底部时间轴 | **有具体技术架构图（芯片/系统框图）、想突出硬核技术感**的项目——结构上最接近典型 Pre-IPO 硬科技投资海报 |
| 日心说科普信息图海报 | 单张海报，中心图解+编号板块+金色奢华配色 | **想要高端/资本市场感、亮点适合编号呈现（如 01/02/03/04）**的项目 |
| 日文 AI 空间一致性笔记 | 手写笔记本实拍风格 | 不适合专业投资材料，太随意 |
| 人体器官健康信息图 | 2x2 多主体网格，加权公式写法 | 不适合单一项目单一海报；加权公式技法可借鉴但视觉语言（spa/医疗）不匹配金融场景 |

默认最常用得上的三选：**香农风（技术架构图为核心）、雅典娜风（对比+时间轴丰富）、日心说风
（编号亮点+高端配色）**——但不要机械套用，实际操作时先看项目材料本身有什么可视化素材
（有没有技术框图、有没有清晰的融资时间轴、亮点是不是天然适合编号呈现），据此调整选哪 3 个，
理由要写清楚。

### 生成流程

1. 读 Teaser（或直接读两条链对外版）,识别项目的核心可视化素材：有没有技术架构图可画、
   有没有可比公司/竞品数据、有没有清晰的时间轴（融资节点/申报节点）、核心数字有哪些
   （估值、规模、增速、退出预期）
2. 从风格库里选 3 个最贴合的，各写一句理由
3. 参照对应风格的 JSON schema 结构（`subject`/`style`/`poster`/`layout.sections`/
   `visual_elements`/`color`/`composition` 这几个字段是共性骨架），把项目真实数据填进去——
   **不用占位符，必须是真实的公司名、真实数字、真实亮点**，跟 Pipeline/Teaser 里的内容
   保持一致，不要重新编
4. 三份提示词整理进一个文件，每份前面加一句风格名 + 选择理由，方便用户直接复制单独一份
   去生成

存到 `08_investor_materials/Infographics提示词_对外版_<日期>.md`。

## 收尾

跟其他对外材料一样，生成后过一遍关键词兜底扫描，然后过一遍人工确认（哪怕这两个只有对外版，
也要过一眼再发出去，不能因为"没有内部版可对比"就跳过检查）：

```
python scripts/check_external_safe.py --input 08_investor_materials/Teaser_对外版_<日期>.md --project-dir <project_dir>
python scripts/check_external_safe.py --input 08_investor_materials/Infographics提示词_对外版_<日期>.md --project-dir <project_dir>
```

确认后跟其他产出物一样，用户要拿文件时提醒对方直接说"把Teaser/信息图提示词发给我"。
