# 投资人材料包编排层

对应 `docs/PRD.md` 第五部分「投资人材料包」。这是分发链、研发链之外的**第三条支线**，
只有在两条主链都跑完之后才触发，产出 Pipeline、研究报告、PPT 大纲之外的另外三份对外
材料：Teaser、Infographics 提示词、Term Sheet。

## 前置条件（触发前必须检查）

Teaser、Infographics 提示词、Term Sheet 依赖的内容（退出预期、可比公司倍数、护城河
判断、谈判条款）横跨两条链，所以触发前先检查这些是不是都在：

```
python scripts/project_status.py --project-dir <project_dir>
```

- `03_pipeline/` 下要有 `Pipeline_对外版_*.xlsx`（分发链跑完）
- `05_screening/` 下要有研判报告（研发链至少跑到定性研判）

**估值（`06_valuation/`）不是硬性前提**——如果项目是天使轮等早期阶段、按规则跳过了
`hardtech-preipo-valuation`，Teaser 里就没有"退出预期"这个板块，不强求。但如果连
`03_pipeline/` 或 `05_screening/` 都缺，就不要往下走，提示用户先把对应的链跑完：

> "生成 Teaser/信息图提示词/Term Sheet 需要两条链都至少跑到出对外版的程度。现在缺 XX，
> 要不要先去把这一步补上？"

**Term Sheet 额外前提，且不能省略**：

1. `05_screening/` 的研判报告要跑完 Step 4（股权治理与条款审查）和 Step 5（退出路径），
   否则没有"必须谈判调整的条款"和"如不能调整就放弃的红线"可用，Term Sheet 第二、三条
   （投资者权利、投资者保护与退出安排）没有实质内容，不要凭空补。
2. `04_forensics/` 建议至少跑过快筛；跑过深读的话，必答项核对表可以直接转成交割先决
   条件，质量更高。如果这一步完全没跑，明确告知用户："材料证伪没跑过，Term Sheet 第五条
   交割先决条件只能写通用条款，没法针对这个项目的具体信息缺口定制，要不要先补一遍快筛？"
   用户坚持跳过的，尊重决定，但这句提示必须说在前面，不能默默用通用模板顶上。
3. Term Sheet 涉及的交易主体、认购金额等参数不在 Pipeline 14 字段范围内，**必须由用户
   明确提供，不能从材料或对外版文件里推断或代填**：
   - 投资方全称（含法律主体类型，如"XX投资中心（有限合伙）"）
   - 拟认购/投资金额
   - 目标公司的实际控制人姓名（用于第三方签署及回购连带责任条款；材料里如果连这个都
     没有，必须明确标注"以公司书面确认为准"，不能瞎写一个名字）
   - 是否要求实际控制人对回购承担连带责任（默认按 05_screening 谈判清单的建议要求，
     用户可以覆盖）
   - 排他期天数、争议解决方式（仲裁/诉讼）、适用法律管辖地（无特殊要求时用默认值，
     见步骤 3 的默认条款，但要让用户知道这是默认值、可以改）
   这些跟商务条件确认（分发链步骤 3）性质一样，是编排层不能替用户猜的硬约束，缺了就
   停下来问，不要假设。

## 只出对外版，没有内部版——但 Term Sheet 是例外，要单独说清楚

Teaser 和 Infographics 提示词设计上就是给机构投资人看的营销材料，不像 Pipeline/研究
报告那样需要"内部版留判断依据、对外版清洗"——**起草时只能读两条链已经生成的对外版文件**
（`Pipeline_对外版_*.xlsx`、`研究报告_对外版_*.md`），不要去翻内部版、研判备忘、疑点
清单这些 L3 文件来"找亮点"。这本身就是最可靠的隔离机制：内部专属的内容压根不会进入
起草者的视野，不需要标记后再删除。

**Term Sheet 做不到这种"完全不接触内部文件"的隔离**，因为它的核心内容（投资者保护
条款、交割先决条件）本来就是从内部研判的谈判清单和材料缺口反推出来的——这是它跟另外
两个产出物本质不同的地方，不能套同一句"只读对外版"就带过去。正确的做法不是回避读取，
而是**转译规则要写清楚、且比 Teaser/Infographics 更严格地跑关键词扫描**（见步骤 3 的
取材范围表 和 `TERM_SHEET_KEYWORDS`）。三者的隔离机制对照：

| | Teaser / Infographics | Term Sheet |
|---|---|---|
| 隔离方式 | 起草时物理上不接触内部文件 | 起草时读取内部文件的特定字段，但逐条转译成中性条款，不复述原文 |
| 允许读取的内部内容 | 无 | 05_screening 的谈判清单/红线条款、04_forensics 的必答项缺口状态（哪些缺、哪些部分披露——不是缺口对应的怀疑分析原文） |
| 关键词扫描表 | `INVESTOR_PACKAGE_KEYWORDS` | `TERM_SHEET_KEYWORDS`（覆盖面更宽，多了怀疑性措辞和 Pipeline 内部列名） |

起草完成后都要跑一遍关键词兜底扫描（同 Pipeline/研究报告用的机制），当作最后一道保险：

```
python scripts/check_external_safe.py --input <草稿文件> --kind teaser --project-dir <project_dir>
python scripts/check_external_safe.py --input <草稿文件> --kind termsheet --project-dir <project_dir>   # Term Sheet 用这个
```

命中不阻塞，但要在人工确认节点里过一遍。

## 步骤 1：生成 Teaser

**结构不锁模板**——参考格式（标题、投资亮点分点论述、有的话附可比公司表、结尾），但具体
分几点、每点讲什么，跟着项目实际情况走，不强求每个项目都套"估值性价比/业绩确定性/发展
潜力/退出预期"这四类。比如天使轮项目没有退出预期数据，就不写这一节，不要为了凑结构编数字。

**必须遵守的信息披露规则**：跟 Pipeline 的加工层是同一套铁律（见
`hardtech-project-triage-matching` 第 1.3 节）——估值定价依据、折扣/倒挂情况、回购条款
存在与否、锁定期、已知重大风险、数据口径，这些**必须如实写**，不能因为 Teaser 是"营销材料"
就只挑好听的说。Teaser 是精简版的推介材料，不是选择性披露的广告。

**取材顺序**：
1. `Pipeline_对外版_*.xlsx` —— 项目简介、入场估值、定价逻辑、投资形式、亮点、目标上市地、
   预计申报时间、退出估值、退出方式、流动性安排
2. `研究报告_对外版_*.md` —— 团队、技术护城河、财务与运营数据、退出路径分析里的客观内容
3. 如果 `06_valuation/` 有产出，只取**退出估值区间**和**目标 IRR 对应的市值预估**这类
   面向标的价值判断的结论；入场价格上限本来就不会出现在对外版材料里，Teaser 也不例外

存到 `08_investor_materials/Teaser_对外版_<日期>.md`。

## 步骤 2：推荐信息图风格 + 生成 Infographics 提示词

用户会把提示词拿去 ChatGPT 的图片生成模型里用，所以最终格式统一用**结构化 JSON**
（不是自然语言段落）——这类模型对 JSON 结构化 prompt 的解析很稳定，且对"这个板块必须
放哪几个精确数字/标签"的控制力比自然语言段落强，适合金融数据类信息图这种容不得数字
写错位置的场景。

### 风格库与选型逻辑

7 种参考风格，各自适配的构图任务不同，选型时按这个逻辑判断，不要固定死用哪 3 个：

| 风格 | 构图任务 | 适合什么样的项目 |
|---|---|---|
| Codex 研讨会 Slides 网格 | 3x3 多页幻灯片缩略图拼贴 | 不适合单张投资海报，除非要出"多页材料预览图" |
| 3x3 B2B SaaS 演示文稿概览 | 3x3 多页产品页面拼贴 | 同上；但里面的 KPI 卡片/趋势图单元适合借鉴局部样式 |
| 雅典娜之鸮信息图海报 | 单张高密度海报，中心大图+多分区+对比表+时间轴 | **护城河/竞品对比丰富、有清晰融资时间轴**的项目 |
| 克劳德·香农复古信息图海报 | 单张海报，标题区+备忘录式数据框+中心技术流程图+底部时间轴 | **有具体技术架构图（芯片/系统框图）、想突出硬核技术感**的项目——结构上最接近典型 Pre-IPO 硬科技投资海报 |
| 日心说科普信息图海报 | 单张海报，中心图解+编号板块+金色奢华配色 | **想要高端/资本市场感、亮点适合编号呈现（如 01/02/03/04）**的项目 |
| 日文 AI 空间一致性笔记 | 手写笔记本实拍风格 | 不适合专业投资材料，太随意 |
| 人体器官健康信息图 | 2x2 多主体网格，加权公式写法 | 不适合单一项目单一海报；加权公式技法可借鉴但视觉语言（spa/医疗）不匹配金融场景 |

默认最常用得上的三选：**香农风（技术架构图为核心）、雅典娜风（对比+时间轴丰富）、日心说风
（编号亮点+高端配色）**——但不要机械套用，实际操作时先看项目材料本身有什么可视化素材
（有没有技术框图、有没有清晰的融资时间轴、亮点是不是天然适合编号呈现），据此调整选哪 3 个，
理由要写清楚。

### 生成流程

1. 读 Teaser（或直接读两条链对外版）,识别项目的核心可视化素材：有没有技术架构图可画、
   有没有可比公司/竞品数据、有没有清晰的时间轴（融资节点/申报节点）、核心数字有哪些
   （估值、规模、增速、退出预期）
2. 从风格库里选 3 个最贴合的，各写一句理由
3. 参照对应风格的 JSON schema 结构（`subject`/`style`/`poster`/`layout.sections`/
   `visual_elements`/`color`/`composition` 这几个字段是共性骨架），把项目真实数据填进去——
   **不用占位符，必须是真实的公司名、真实数字、真实亮点**，跟 Pipeline/Teaser 里的内容
   保持一致，不要重新编
4. 三份提示词整理进一个文件，每份前面加一句风格名 + 选择理由，方便用户直接复制单独一份
   去生成

存到 `08_investor_materials/Infographics提示词_对外版_<日期>.md`。

## 步骤 3：生成 Term Sheet（投资条款清单）

Term Sheet 跟 Teaser/Infographics 的定位不一样：后两者是"介绍这个机会"的营销材料，
Term Sheet 是**准备实际发给标的公司、用来锁定认购额度**的交易文件，措辞不严谨或条款
遗漏是真实的商业/法律风险，不是"内容不够精彩"这种程度的问题。触发词例如"出具Term
Sheet""起草TS""帮我把这个额度的条款清单写出来"。

### 取材范围（哪些能用、哪些不能用，逐条对照）

| 来源 | 能取的内容 | 转译方式 | 不能取的内容 |
|---|---|---|---|
| `03_pipeline/Pipeline_对外版_*.xlsx` | 入场估值、投资形式、交易金额、退出方式、流动性/锁定安排 | 直接引用，估值类数字改写成"不超过 XX 亿元"的上限口径（见下方"估值条款写法"），不写死成既定事实 | Pipeline 内部版的 O-X 十列（内部定级、命中红线等），Term Sheet 的起草者不应该打开内部版文件 |
| `05_screening/`（研判报告 Step 4/5） | "必须谈判调整的条款"清单、"如不能调整就放弃的红线"、退出路径与情景推演里的客观结论 | 逐条转成 Term Sheet 对应条款（清算优先权、反稀释、回购主体等），不复述评分依据 | A/B/C 定级本身、D1-D5 信号灯、MOIC/IRR 数字、"🟡有条件参与"这类结论表述 |
| `04_forensics/`（必答项核对表，若有深读） | 每一项的**状态**（缺失/部分/已获）——只取状态，不取该项对应的三段式疑点原文 | 状态="缺失"或"部分"的项，转成交割先决条件里"公司应提供/确认……"的条目 | 疑点三段式里的"冲突所在"分析、材料可信度分级（M1-M4）标注、任何怀疑性措辞 |
| `06_valuation/`（若有） | 净资产安全垫结论、退出估值区间 | 可用于判断估值条款的谈判空间，但入场价格上限本身不写进条款 | 入场价格上限的具体数字、目标 IRR 反推过程 |
| 用户直接提供 | 投资方全称、认购金额、实际控制人姓名、排他期天数、争议解决方式等 | 直接填入 | — |

**估值条款写法（重要，不是可选的格式偏好）**：Term Sheet 里的估值、认购额度这类数字，
统一写成"不超过/不高于 XX"的授权上限句式，不写成"投前估值为 XX 亿元"这种既定事实句式。
这不是套模板凑格式——写成既定事实，一旦材料证伪或估值定价阶段发现依据不牢（比如外部
核查发现融资体量对不上材料自述），Term Sheet 已经把不牢靠的数字当承诺发出去了；写成
"不超过"，估值基础生变时甲方有台阶下、有权重新谈，这个空间是靠句式本身留出来的，不是
靠事后解释。同理，认购金额可以是确定数字（这个通常是用户主动给的、真实想投的额度），
但估值、对应股权比例这类依赖对方数据的字段要用上限句式。

### 结构（默认模板，可按项目实际情况增减条款，不强求每一条都出现）

1. 交易概述（表格：投资方/目标公司/实际控制人/交易性质/金额/估值上限/资金用途）
2. 估值与出资安排
3. 投资者权利与公司治理（信息权、董事会观察员或席位——按认购比例判断是否够格要求正式
   席位、保护性一票否决权、优先购买权与共同出售权、领售权、反稀释、最惠国待遇）
4. 投资者保护与退出安排（优先清算权、历史轮次优先级、里程碑/业绩承诺——**优先用产品/
   营收里程碑，避免与公司市值直接挂钩的对赌**，见下方"里程碑条款与 IPO 清理"、回购权
   及义务主体、对赌与特殊权利条款的 IPO 清理安排）
5. 陈述与保证
6. 尽职调查与交割先决条件（把 04_forensics 必答项缺口和 05_screening 关键变量清单
   转译成的条目，全部放这一条）
7. 排他期
8. 保密
9. 费用
10. 有效期与约束力（明确哪几条具有法律约束力：通常是排他期、保密、费用、适用法律与
    争议解决、本条自身；其余条款不具约束力，仅为签署正式协议的基础）
11. 后续安排
12. 适用法律与争议解决
13. 签署页（甲方/乙方/实际控制人三方，实际控制人是回购连带责任的义务人时必须单独签署）

**里程碑条款与 IPO 清理**：科创板审核对赌协议清理有明确的监管口径——发行人不作为对赌
义务人、不导致控制权变化、不与市值挂钩、不严重影响持续经营或其他投资者权益，满足这四条
的可以不强制清理。起草第 4 条时按这个口径设计：业绩承诺用具体的产品里程碑（量产时点、
营收金额）而非市值或估值倍数，回购/对赌的义务人优先落在实际控制人而非公司本身（公司
作为义务人在拟合格发行时通常必须清理，实际控制人作为义务人的操作空间更大），并加一条
"启动上市辅导前另行签署条款清理及恢复协议"的安排。这不是可选的严谨性加分项，是直接
影响这份 Term Sheet 里的条款将来能不能保留到 IPO 报告期的实质问题。

### 交付格式

**必须同时产出 Word 和 Markdown 两个文件**，内容一致，Word 版用于正式发送/打印/让
对方法务批注，Markdown 版用于内部存档、后续用 git 追踪修改历史：

- `08_investor_materials/TermSheet_<目标公司>_<日期>.md`
- `08_investor_materials/TermSheet_<目标公司>_<日期>.docx`（用 `docx` skill 生成，
  参照该 skill 的排版规范——标题、章节标号、表格双宽度设置等，不要输出纯文本堆砌）

两个文件必须逐条对应，不能出现"Markdown 里有这一条、Word 里漏掉"的情况——生成完
用 `pandoc -t markdown TermSheet_*.docx` 或直接读取 docx 内容做一次条款计数比对。

### 步骤内的人工确认节点

Term Sheet 涉及真实的商业承诺和法律约束条款（排他期、保密、争议解决具有法律约束力，
一旦签署即生效），起草完成后除了跑关键词扫描，还要过一遍比 Teaser/Infographics 更
具体的确认清单，不能只问"可以发送吗"：

> □ 投资方全称、认购金额、实际控制人姓名均已由用户本人确认，不是从材料里猜的
> □ 估值/股权比例相关条款用的是"不超过"上限句式，没有把未经核实的数字写成既定事实
> □ 第 6 条交割先决条件覆盖了 04_forensics 必答项核对表里所有"缺失/部分"状态的项
> □ 回购条款的义务主体、连带责任安排已按 05_screening 谈判清单的建议写入，不是只写了
>   触发条件和利率
> □ 对赌/里程碑条款用的是产品/营收里程碑，没有与公司市值或估值倍数直接挂钩
> □ 没有出现我方专项基金自身的管理费/Carry/认购费等 LP-GP 条款
> □ 关键词扫描（`--kind termsheet`）结果已看过并确认无误
> □ 是否需要律师在发出前再审阅一遍binding条款（排他期/保密/争议解决）——这份清单不
>   替代法律意见，只是内容完整性的检查

```
python scripts/check_external_safe.py \
  --input 08_investor_materials/TermSheet_<目标公司>_<日期>.md \
  --kind termsheet --project-dir <project_dir>
```

用户确认后：
```
python scripts/audit_log.py append <project_dir> --actor user \
  --step "Term Sheet 发送前检查确认" --detail "用户确认可以发送，投资方=<全称>，金额=<金额>" \
  --pause-type confirm
```
