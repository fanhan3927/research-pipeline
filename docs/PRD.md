# Research Pipeline 自动化程序 — 产品需求文档（PRD）

**文档状态**：v0.5，Phase 1-5 已完成，新增投资人材料包（Teaser + Infographics 提示词）
**密级**：内部文件
**编写日期**：2026-08-09
**依赖资产**：`hardtech-project-triage-matching`、`pipeline-intake`、`preipo-material-forensics`、`pe-hardtech-screening`、`hardtech-preipo-valuation`（五个已存在的 Claude Skill）

---

## 一、背景

团队目前已经有五个独立的 Claude Skill，覆盖两类工作：

- **分发链**（`triage-matching` → `pipeline-intake`）：把一个新项目变成一份可以发给机构投资人的 Pipeline 记录，并给出该推给谁。
- **研发链**（`preipo-material-forensics` → `pe-hardtech-screening` → `hardtech-preipo-valuation`）：把一份公司自述材料，还原成有依据的投资判断和入场价格上限。

这五个 skill 各自独立、职责清晰，但**串联它们、传递中间产物、做人工确认、生成最终交付物**目前完全靠人工操作：手动复制粘贴上一步的输出给下一步、手动决定什么时候该问用户、手动整理最终文件、手动检查对外版有没有脱敏干净。这一套操作繁琐且容易出错（尤其是脱敏遗漏，参考手册中反复强调的"发错文件是最常见的泄露事故"）。

本项目要做的，**不是重做这五个 skill 的判断逻辑**，而是在它们之上加一层**编排层**，把"人工串联五个 skill、做取舍判断、生成成品文件"这件事自动化。

## 二、项目目标

1. 用户在对话开始时选择模式（分发链 / 研发链），后续按模式自动依次触发对应的 skill。
2. 编排层在需要人工输入或确认的节点主动提问，其余环节自动执行，减少用户手动操作。
3. 分发链最终产出**结构化 Pipeline Excel**（内部版 + 对外版）。
4. 研发链最终产出 **约 12 页的 PDF 研究报告** 与 **15 页的 PPT Deck 大纲（Markdown）**，且分别产出**内部完整版**与**对外脱敏版**。
5. 两条链都跑完后，追加产出 **Teaser（Markdown）** 与 **Infographics 提示词（JSON，供 ChatGPT 图片生成模型使用）**，两者都只出对外版，不做内部版（v0.5 新增，见第六部分投资人材料包）。
6. 全流程可追溯（每个项目的每一步输入/输出/人工决定都留痕）、可复现（同样的输入 + 同样的人工决定，能重新跑出同样的结果）。
7. 严格延续现有手册中的信息隔离铁律，不能因为自动化而增加信息泄露风险。

## 三、名词与角色定义

| 术语 | 含义 |
|---|---|
| 分发链 | `hardtech-project-triage-matching` → （商务条件确认）→ （加工层）→ `pipeline-intake` → （对外版生成） |
| 研发链 | `preipo-material-forensics` → `pe-hardtech-screening` → `hardtech-preipo-valuation` → （报告生成层，新增） |
| 投资人材料包 | 两条链都跑完后的第三条支线（v0.5 新增），产出 Teaser + Infographics 提示词，只取两条链的对外版文件，不接触内部版 |
| 编排层 | 本项目新增的部分，负责按顺序调用五个 skill、管理中间产物、在关键节点向用户提问、生成最终交付文件 |
| L1 / L2 / L3 | 沿用原手册的信息层级：L1 可发给项目方/转让方，L2 可发给机构投资人，L3 仅内部可见 |
| 关键节点 | 流程中无法由编排层自动推进、必须暂停的步骤，分两类（见 6.5）：**人工确认**（等用户本人输入或决定）与**外部等待**（等项目方/转让方等外部方回复后，由用户重新触发） |

角色：**用户本人**（中介 + 投资研究双重角色），编排层不引入新的外部角色。

## 四、范围

**本期（v1）范围内**：
- 分发链全流程编排：研判 → 商务条件确认（人工）→ 加工层 → 入库 → 内部列回填 → 对外版生成 → 发送前检查清单。
- 研发链全流程编排：材料证伪（快筛/深读判断，人工）→ 定性研判 → 估值定价（可比公司数据，人工提供）→ **新增报告生成层**（12 页 PDF + 15 页 PPT 大纲，内部版与对外脱敏版）。
- 两链自动衔接：分发链定级 A/B 自动询问是否启动研发链；研发链的退出估值自动回填 Pipeline，入场价格上限不进 Pipeline。
- **投资人材料包**（v0.5 新增）：两条链都跑完后触发的第三条支线，产出 Teaser（Markdown）+ Infographics 提示词（JSON），只出对外版，取材范围限定在两条链已生成的对外版文件。
- 项目级文件归档与操作日志（可追溯、可复现的基础设施）。

**本期不做**（Out of scope，留待后续版本）：
- 不新建/修改五个现有 skill 内部的判断逻辑（红线阈值、定级权重、估值方法等）——编排层只调用，不改造。
- 不做多用户协作、权限管理、Web 界面；本期仍是 Claude Code 对话 + 本地文件的形态。
- 不做与外部系统（邮箱自动发送、CRM）的直接对接；对外版文件生成后仍由用户手动发送。
- 不做批量/并发多项目处理；本期按单项目串行跑。

## 五、总体技术方案

**形态：对话编排为主**（新增编排层，在 Claude Code 对话中依次触发五个现有 skill；胶水脚本只负责文件生成、转换、脱敏，不承担判断职责）。

选择这个形态的原因：五个 skill 里封装的判断逻辑（红线检查、七步研判、IRR 反推等）非常依赖模型的语言理解和领域知识，用代码重写成本高、还可能与原 skill 的口径不一致，产生"两套标准打架"的问题。编排层复用现有 skill 的全部 prompt 能力，只新增"胶水"部分。

### 5.2 新增的"报告生成层"（研发链专属，五个 skill 里没有）

`forensics`、`screening`、`valuation` 三个 skill 各自产出的是独立文档（事实清单/疑点清单、七步研判报告、估值报告），原手册里这三份文档本身就是最终交付物，从未要求整合成一份 PDF 或 PPT。而本项目要求的最终产出是"12 页 PDF 研究报告"和"15 页 PPT 大纲"，这是**编排层需要新增的整合与排版能力**，具体做法：

1. 三份产出各自完成后，编排层把三者的关键内容抽取整合成一份统一结构的研究报告大纲（章节建议：项目概览 / 材料可信度与核心疑点 / 团队与治理 / 技术与护城河 / 财务与数据质量 / 退出路径与确定性 / 估值与入场价格测算 / A-B-C 结论与建议，共约 8 个章节）。**12 页 / 15 页均为软性篇幅目标，不是硬性页数要求**——某个项目疑点特别多、或某一章节没有内容，允许相应增减，不强行填充或裁剪。
2. **脱敏机制**：起草内部版 Markdown 草稿时，把入场价格上限、IRR 反推过程、A/B/C 定级、go/no-go 结论、M1-M4 可信度分级标注、疑点三段式中的"冲突所在"分析，包在 `<!-- external:exclude -->` … `<!-- /external:exclude -->` 标记之间。`scripts/generate_report_versions.py` 只做机械转换——按标记删除内容、跑一遍关键词兜底扫描——不自己判断语义；语义判断（哪些内容属于内部专属）在起草阶段由编排指令（见 `orchestrator/rd-chain/SKILL.md`）里的规则表完成。标记不配对时脚本直接报错拒绝生成，不会"尽量猜"。
3. 调用 `pdf` skill 把上一步产出的内部版/对外版 Markdown 分别渲染成 PDF。
4. 产出 15 页 PPT Deck 大纲，**只输出结构化 Markdown，不调用 `pptx` skill、不生成实际 .pptx 文件**——用户会用自己的其他工具把这份 Markdown 大纲转成正式 PPT，编排层不需要覆盖这一步。大纲的内部版/对外版复用同一套脱敏机制和脚本（`--kind deck`）。

## 六、详细流程设计

### 6.1 启动：选择模式

用户开始一个新项目处理时，编排层第一句话询问：

> 这个项目走哪条链？① 分发链（要给资金方推）② 研发链（要出研判报告/估值）③ 两条都要（先分发链，A/B 档自动询问是否接研发链）

### 6.2 分发链流程

| 步骤 | 动作 | 执行方 | 是否为关键节点 |
|---|---|---|---|
| 0 | （材料很粗，仅够跑红线检查）生成空白采集表发给项目方/转让方/FA | **外部等待**（编排层生成 Word 采集表后暂停，等用户拿到对方填回的采集表后重新上传触发继续） | **是** |
| 1 | 研判（触发 `hardtech-project-triage-matching`） | 自动 | 否 |
| 2 | 命中红线 → 终止归档 / 定级 C → 存档观察 / 定级 A、B → 继续 | 自动判断分支 | 否（分支逻辑自动，但结果会告知用户） |
| 3 | 商务条件确认（有没有 FA 费、折扣空间） | **人工**（编排层暂停，等待用户电话确认后回填） | **是** |
| 4 | 加工层（剥离禁止上行信息 + 重写亮点） | 自动 | 否 |
| 5 | 入库（触发 `pipeline-intake`，提取 14 字段） | 自动 | 否 |
| 5.1 | 若入库后仍有字段缺失，生成信息缺口清单发给项目方 | **外部等待**（同步骤 0，等用户拿到回复后重新上传触发继续；缺口不影响先出一版"缺失字段标 null"的 Pipeline） | 否（不阻塞主流程，缺口清单是并行支线） |
| 6 | 内部列回填（O-X 十列） | 自动（基于第 1、3 步结果） | 否 |
| 7 | 生成对外版（跑 `make_external_pipeline.py`） | 自动 | 否 |
| 8 | 发送前检查清单 | **人工**（编排层列出手册中的 6 项检查，等待用户确认后才标记"可发送"） | **是** |

### 6.3 研发链流程

| 步骤 | 动作 | 执行方 | 是否为关键节点 |
|---|---|---|---|
| 1 | 材料证伪（触发 `preipo-material-forensics`，默认快筛） | 自动 | 否 |
| 2 | 是否深读 | **人工**（编排层询问："快筛结果如上，是否要深读？"） | **是** |
| 3 | 深读，生成内部研判备忘 + 外发《补充材料清单》（Word） | 自动 | 否 |
| 3.1 | 把《补充材料清单》发给项目方，等待材料补齐 | **外部等待**（编排层暂停在此，用户拿到项目方回复的材料后说"材料回来了，重新上传"触发继续，编排层只重跑受影响部分，不重复已完成的分析） | **是** |
| 4 | 定性研判（触发 `pe-hardtech-screening`，基于移交字段表；若步骤 3.1 未等到回复，允许用户选择"先按现有信息推进，缺项在报告中标注"） | 自动 | 否 |
| 5 | 可比公司 PE/PS 倍数输入 | **人工**（编排层明确提示这是硬约束，必须用户提供，不代填） | **是** |
| 6 | 估值定价（触发 `hardtech-preipo-valuation`） | 自动 | 否 |
| 7 | 整合三份产出，生成 12 页 PDF 研究报告（内部版） | 自动 | 否 |
| 8 | 生成 15 页 PPT 大纲 Markdown（内部版） | 自动 | 否 |
| 9 | 生成对外脱敏版 PDF + PPT 大纲 | 自动（按第七节脱敏规则） | 否 |
| 10 | 对外版发送前检查 | **人工**（同分发链逻辑，确认脱敏无遗漏后才标记"可发送"） | **是** |

### 6.4 两链自动衔接（全流程自动衔接）

1. **分发链 → 研发链**：分发链第 2 步定级为 A 或 B 时，编排层自动提示："该项目定级为 {A/B}，是否启动研发链做深度研判？" 用户确认后跑 `init_project.py --chain rd`，在**同一个项目目录**上补齐研发链子目录（找同名目录扩展，不新建），已有材料、triage 结论中可复用的字段直接传给研发链的第一步（避免重复上传）。
2. **研发链 → 分发链**：研发链第 6 步估值定价完成后，跑 `backfill_exit_valuation.py` 把"退出估值"回填进该项目的 Pipeline 内部版，并自动重新生成一份对外版（内部版与对外版都可含退出估值，因为它是对标的的判断，不是议价筹码）；这份新生成的对外版会自动追加一条"需要重新走发送前检查"的人工确认记录，不会因为"之前检查过旧版本"就被默认放行。
3. **入场价格上限严禁写入 Pipeline 任何版本**——这条规则不是靠脚本里的运行时检查来遵守的，而是**结构上做不到**：`backfill_exit_valuation.py` 的参数里只有"退出估值"一个可写字段，没有提供写其他字段的接口；即使用户手工把入场价格上限之类的字段加进了内部版 Excel，`make_external_pipeline.py` 的白名单机制也会自动排除它，并额外打印一条结构性提醒（检测字段名含"价格上限""议价底价"等），确保这条硬拦截是可见的，不是悄悄发生的。

### 6.5 两类暂停的区别

编排层的"暂停"不是一种，是两种，处理方式不同：

| | 人工确认 | 外部等待 |
|---|---|---|
| 谁来解除暂停 | 用户本人直接回答/决定 | 用户拿到项目方等外部方的回复后，手动触发继续 |
| 典型场景 | 商务条件确认、是否深读、可比公司倍数、发送前检查 | 空白采集表待填回、信息缺口清单待补、补充材料清单待补 |
| 交互方式 | 单次对话内多轮追问，编排层原地等用户回答 | 编排层原地等待；若用户中途离开对话，恢复方式是用户重新打开对话说"材料/表格回来了"并重新上传，编排层从暂停点续跑，不重复已完成的步骤 |
| 是否阻塞主流程 | 是（不确认无法继续） | 视情况：分发链第 5.1 步不阻塞（先出一版缺失字段标 null 的 Pipeline，缺口回来了再更新）；其余外部等待默认阻塞，除非用户明确选择"先按现有信息推进" |

两类暂停都要写入 `audit_log.md`：人工确认记录"谁在什么时间确认了什么"，外部等待记录"什么时间发出等待、什么时间收到回复、恢复后重新跑了哪些步骤"。

### 6.6 投资人材料包（v0.5 新增）

两条链都跑完之后的第三条支线，产出两份新的对外材料，触发词例如"生成Teaser""出个信息图提示词"。

**触发前置条件**：`03_pipeline/` 要有 Pipeline 对外版，`05_screening/` 至少要有研判报告。
估值（`06_valuation/`）不是硬性前提——早期阶段项目按规则跳过估值 skill 的，Teaser 里对应
就没有"退出预期"这一节，不强求凑数据。跑 `project_status.py` 确认前置条件是否满足。

**只出对外版的隔离机制**：跟 Pipeline/研究报告"内部版打底、脚本清洗出对外版"的做法不同，
Teaser 和 Infographics 提示词起草时**只读两条链已经生成的对外版文件**，不接触任何内部版/
研判备忘/疑点清单——内部专属内容压根不会进入起草者的取材范围，这本身就是隔离机制，
不需要标记后再删除。起草完成后仍跑一遍关键词兜底扫描（`check_external_safe.py`，用
`banned_keywords.INVESTOR_PACKAGE_KEYWORDS`，即两条链对外版关键词表的并集）作为最后一道
保险。

**Teaser（Markdown）**：结构不锁死模板，跟着项目实际情况定，参考格式而非强制格式；但必须
遵守跟 Pipeline 加工层同一套"必须如实披露"规则（估值依据、折扣/倒挂、回购条款、锁定期、
重大风险、数据口径不能选择性隐藏）——Teaser 是精简版推介材料，不是可以只挑好话说的广告。

**Infographics 提示词（JSON）**：产出给 ChatGPT 图片生成模型直接使用的提示词，不产出图片
本身。格式统一用结构化 JSON（不是自然语言段落）——对这类模型而言，JSON 结构化 prompt
在"精确控制某个板块该放哪个数字/标签"上比自然语言段落更可靠，适合金融数据类信息图。
从一个 7 种风格的参考库里，结合项目实际素材（有没有技术架构图、有没有清晰的融资时间轴、
亮点是否适合编号呈现）挑 3 种最贴合的风格，各写一句选择理由，再分别填入真实项目数据生成
完整提示词——不用占位符，跟 Teaser/Pipeline 里的内容保持一致。

## 七、信息隔离与脱敏规则

编排层必须继承原手册的三条铁律，并新增研发链报告的对外脱敏规则：

**沿用铁律**：
1. 研判链（研发链）任何产出默认不外发，尤其入场价格上限。
2. Pipeline 内部版不外发，只发脚本生成的对外版。
3. 先研判后入库，顺序不能颠倒（编排层的步骤顺序本身保证这一条，不允许用户跳过第 6.2 节步骤 3 直接到步骤 5）。

**新增：研发链对外版脱敏规则**（对应第五节的报告生成层）：

| 内部版包含 | 对外版处理 |
|---|---|
| A/B/C 定级、go/no-go 结论 | 删除 |
| 入场价格上限、目标 IRR 反推过程 | 删除 |
| 数据可信度分级（M1-M4）、疑点三段式中的"冲突所在"分析 | 删除，只保留"需项目方回答"部分（若需要外发问题清单） |
| 退出估值区间、退出路径分析 | 保留（判断标的价值，不是议价筹码） |
| 团队/技术/护城河的客观描述 | 保留，但对未经验证的表述加注"未经独立核实" |

对外版生成后，同分发链一样，编排层要跑一遍关键词扫描（如"入场""IRR""定级""疑似""不实""压价"等）作为脱敏兜底检查，并在人工确认节点（6.3 步骤 10）列出扫描结果供用户复核。

## 八、可追溯与可复现设计

1. **项目级归档**：每个项目在 `projects/<项目名>_<日期>/` 下有固定子目录结构（见 5.1），原始材料与每一步产出都落盘保存，不覆盖旧版本（新版本加时间戳后缀）。
2. **操作日志**：每个项目目录下维护 `audit_log.md`，记录：时间戳、触发的 skill/脚本、输入文件、输出文件、人工确认内容（如"用户于 2026-08-09 14:32 确认 FA 费 2%"），以及外部等待的起止时间与恢复后重跑的步骤范围（如"2026-08-09 发出补充材料清单 → 2026-08-14 材料回填，重跑步骤 4-10"）。
3. **可复现**：只要 `00_raw/` 原始材料和 `audit_log.md` 里的人工确认记录不变，重新跑一遍编排层应产出内容一致的结果（模型输出的自然语言措辞允许有细微差异，但结构化字段、定级、数字结论应一致）。
4. **跨会话接续**：`audit_log.md` 刻意保持成只追加的流水账，不做成需要维护状态转换的结构化状态机——`scripts/project_status.py` 在这份流水账之上提供一个只读的速览视图（目录完成情况 + 历史暂停记录），换了对话或隔了几天回来接着做时，先跑一下这个脚本，不用翻全部日志或凭记忆判断进度。

## 九、非功能需求

- **标准化**：Pipeline Excel 字段、PDF 报告章节结构、PPT 大纲结构在所有项目间保持一致的模板，便于直接使用或二次编辑。
- **低操作负担**：除第六节标注的关键节点外，用户不需要在中间步骤手动复制粘贴或手动触发下一个 skill。
- **安全默认**：任何"是否外发"的判断，默认选择更保守的一侧（即默认不外发、默认需要人工确认），除非用户明确要求跳过。

## 十一、验收标准

1. 用户上传一份分发链项目材料，全程只在标注的关键节点被追问，最终拿到内部版+对外版 Pipeline Excel，对外版通过 6 项人工检查清单。
2. 用户上传一份研发链项目材料，全程只在标注的关键节点被追问，最终拿到内部版+对外版的 12 页 PDF 与 15 页 PPT 大纲，对外版不含入场价格上限、内部定级等禁止信息。
3. 分发链定级 A/B 后，编排层能自动询问是否启动研发链，且研发链结果能自动回填退出估值到对应 Pipeline 行。
4. 任意一个项目的 `audit_log.md` 能够还原出该项目从原始材料到最终交付物的完整操作轨迹。
5. 一个项目两条链都跑完后，用户能拿到 Teaser（Markdown）与 3 份 Infographics 提示词（JSON），内容全部取自两条链的对外版文件，不含入场价格上限/内部定级等禁止信息；如果项目跳过了估值步骤，Teaser 里对应的退出预期章节应如实缺省，不编造数字。

## 十二、已确认事项（本轮定稿）

1. **PPT 大纲只出 Markdown**：不调用 `pptx` skill、不生成实际 .pptx 文件，用户会用自己的其他工具把 Markdown 大纲转成正式 PPT，编排层的职责到"结构化 Markdown"为止。
2. **12 页 / 15 页均为软性篇幅目标**：允许按项目实际情况自主增减，不强行填充或裁剪到固定页数（见 5.2）。
3. **暂停机制分两类**：人工确认在单次对话内多轮追问、原地等待用户回答；外部等待（等项目方等外部方回复）不强求用户守在对话里，用户拿到回复后重新上传/说一句"回来了"即可从暂停点续跑（见 6.5）。
