# 硬科技项目录入 · 傻瓜式操作指南

> 面向日常操作，不需要看懂代码。技术细节见 `docs/PRD.md` 和 `orchestrator/*/SKILL.md`，
> 这份指南只回答"我现在该做什么"。

---

## 0. 开始前，先确认三件事

1. **分支**：本地/对话所在的仓库要在 `main` 分支上，且是最新的。
   ```
   git checkout main && git pull
   ```
   以后不需要为了"录一个新项目"专门开分支——项目数据本来就不进 git（见第 6 节），
   只有改工具代码本身才需要开新分支。

2. **材料在手**：至少要有项目名称、所属赛道、基础的 BP/企业介绍/财务数据（哪怕不全）。
   材料太粗（只有几行字）也能开始，系统会自动生成一份采集表让你去问项目方要。

3. **想清楚一件事——这个项目你是什么角色**：
   - 你是**中介/撮合方**，要收财务顾问费、把项目推给资金方 → 走**分发链**
   - 你是**直接投资人**，要自己出深度研判和估值决定投不投 → 走**研发链**
   - 两个都要 → 都走，系统会自动衔接，不用重复上传材料

如果拿不准，直接把材料丢给系统，问它："这个项目该走分发链还是研发链？"，系统会替你判断。

---

## 1. 开场怎么说

打开对话，把材料贴上去或上传附件，说一句话就行，不需要背记任何命令：

| 你想做什么 | 直接这么说 |
|---|---|
| 要推给资金方 | "这个项目走分发链" / "帮我筛一下这个项目，走分发链" |
| 要自己做深度研判 | "这个项目走研发链" / "帮我把这个项目拆一下，出研判报告" |
| 不确定 | "这个项目该走分发链还是研发链，帮我判断" |
| 两个都要 | "这个项目两条链都要跑" |

系统会自动在 `projects/<项目名>_<日期>/` 下建好目录骨架，不用你自己建文件夹。

---

## 2. 分发链：全程会问你什么

按顺序会经过下面这些节点，**加粗的"要你回答"是必须停下来等你的**，其余都是自动的：

| 顺序 | 系统做什么 | 要你回答什么 |
|---|---|---|
| 0 | 适用性预检 | 系统会先问三个是非题（赛道对不对口、是不是老股/成长期增资、你是不是中介身份），据实回答 |
| 1 | 材料太粗时，生成一份空白采集表 | 把表发给项目方/转让方/FA，等对方填完拿回来，跟系统说"材料回来了" |
| 2 | 跑红线检查、定级 A/B/C | 无（自动出结果，命中红线或定级 C 会告诉你流程到此结束） |
| 3 | **商务条件确认** | **有没有财务顾问费？收几个点？老股折扣空间还有多少？如果都没有，要不要放弃或只做轻度撮合？** |
| 4-5 | 加工、入库 | 无（自动） |
| 6-7 | 内部列回填、生成对外版 Pipeline | 无（自动） |
| 8 | **发送前检查清单** | **对着清单里 6 项逐条确认（只有 14 列、没有批注、文件名是"对外版"等），确认后才能发** |

**拿到的东西**：`03_pipeline/Pipeline_对外版_<日期>.xlsx`——这是唯一能往外发的文件，
`Pipeline_内部版.xlsx` 任何时候都不能发出去。

定级是 A 或 B 时，系统会顺手问你要不要接着跑研发链，回答"要"或"不要"都可以。

---

## 3. 研发链：全程会问你什么

| 顺序 | 系统做什么 | 要你回答什么 |
|---|---|---|
| 1 | 材料证伪（默认快筛，一页纸） | 无（自动） |
| 2 | **是否深读** | **快筛结果如果疑点不致命，决定要不要花时间深读、出完整问题清单** |
| 3 | 深读，生成问题清单 | 无（自动出内部备忘 + 外发问题清单 Word） |
| 3.1 | 把问题清单发给项目方 | **等材料回来再继续，还是先按现有信息推进（缺项标"待补充"）？** 两种都行，跟系统说清楚选哪个 |
| 4 | 定性研判（七步法） | 无（自动） |
| 5 | **给可比公司倍数** | **这一步系统不会替你猜**——报几家同赛道可比公司的 PE/PS 倍数、公司名、取数时点 |
| 6 | 估值定价 | 无（自动） |
| 7-9 | 整合成 12 页报告 + 15 页 PPT 大纲，内部版/对外版都出 | 无（自动） |
| 10 | **对外版发送前检查** | **确认对外版里没有定级结论、没有入场价格上限、没有可信度分级这些内部专属内容** |

**拿到的东西**：`07_report/` 下的内部版和对外版 PDF、PPT 大纲 Markdown。
**内部版默认不外发**，哪怕检查通过了也只发标"对外版"的那份。

---

## 4. 两条链怎么衔接（不用你操心，但要知道发生了什么）

- 分发链定级 A/B 后 → 自动问你要不要接研发链 → 同意的话直接在同一个项目目录上补齐，
  **不用重新上传材料**。
- 研发链算出退出估值后 → 自动回填进这个项目的 Pipeline（内部版+对外版都会更新），
  并且会提醒你"这份新对外版也要重新走一遍发送前检查"，不能因为之前查过旧版本就直接发。
- **有一条铁律，任何情况下都不会破**：入场价格上限（研发链算出来的心理价位）**永远
  不会进 Pipeline**，不管是内部版还是对外版。这不是靠自觉遵守，是脚本结构上就不给
  写这个字段的接口。

---

## 5. 两条链都跑完之后：投资人材料包

这是第三条支线，两条链都要跑到"至少出了对外版 Pipeline"和"至少出了定性研判报告"
才能触发。三份产出物，可以只要其中一份，不强制打包：

| 你想要 | 直接说 |
|---|---|
| 一页纸推介材料 | "生成 Teaser" |
| 用来生成海报/信息图的提示词 | "出个信息图提示词" |
| 要实际发给标的公司、锁定认购额度的条款文件 | "出具 Term Sheet" / "帮我起草 TS" |

**Term Sheet 比另外两个多一步准备工作**，因为这几样东西系统不会替你猜，必须你自己给：

- 投资方全称（比如"北京创势创新投资中心（有限合伙）"）
- 拟认购金额
- 目标公司实际控制人姓名
- 排他期想定多少天（不说的话默认 60 天）
- 出问题走仲裁还是诉讼（不说的话会用默认条款，但会提醒你这是默认值）

**拿到的东西**：`08_investor_materials/` 下，Teaser 是 Markdown，信息图提示词是 JSON
写在 Markdown 文件里，Term Sheet 是 **Word + Markdown 两份、内容对得上**。

三份出完后系统都会自己跑一遍关键词扫描，把命中的地方念给你听，你确认一遍没问题
才算完——这一步不能跳，哪怕东西看着已经很干净了。

## 6. 项目数据放在哪、会不会不小心传上网

- 每个项目单独一个文件夹：`projects/<项目名>_<日期>/`，下面按步骤分好子目录，
  原始材料、每一步产出、最后的交付物都在里面，不会互相覆盖。
- **这个文件夹整个不会被提交到 git**（`.gitignore` 里写死了 `projects/*/`），
  项目材料再敏感也不会因为"忘记加到忽略名单"而泄露到代码仓库里。
- 只有 `orchestrator/`、`scripts/`、`docs/` 这些工具代码本身会进 git，跟具体某个
  项目的商业机密无关。

**换了个对话、隔了几天回来接着做**，先跑一句，看看上次卡在哪：
```
python scripts/project_status.py --project-dir projects/<项目名>_<日期>
```
它会告诉你哪些目录已经有产出、上次是在哪个"人工确认"或"外部等待"的节点停下的，
不用凭记忆猜。

## 7. 最容易踩的几个坑

- **别把材料直接怼给分发链、跳过步骤 -1 的适用性预检**——早期天使轮、纯消费类项目
  硬套分发链的规则，会得到一个"看起来完整、其实没什么信息量"的结论。系统本身会先
  问这三条，据实回答就行，不要为了"图省事"随便说都符合。
- **商务条件（步骤 3）和可比公司倍数（研发链步骤 5）系统绝对不会替你编**——这两处
  被问到时如果一时答不上来，如实说"还没谈"或"手头没有可比数据"，比瞎编一个数字
  更安全，系统会等你或者给出替代方案，不会卡死。
- **对外版发出去之前，人工检查清单是真的要过一遍，不是走形式**——关键词扫描只是
  兜底，扫描没命中不等于一定安全，最后拍板还是要人看一眼。
- **Term Sheet 里涉及排他期、保密这些具有法律约束力的条款**，建议正式发给对方之前
  让懂法务的人再看一眼，系统给的清单只保证内容完整，不能替代法律意见。
- **旧的开发分支不用管**——只要工具代码本身没有要改的，你永远只需要在 `main` 上
  操作，不需要关心分支合并这些事。
